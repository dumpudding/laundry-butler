## Purpose

This file records stable project paths, verified hardware mappings, safety rules, successful methods, and recurring failure points for future ChatGPT, Claude, Codex, or other agents working on Laundry Butler.

Update this file when:

- a stable path or hardware mapping is established;
- a method succeeds and should be repeated;
- an unexpected failure reveals a reusable lesson;
- a safety assumption is confirmed or disproven;
- a project milestone changes the correct next step.

Do not fill this file with:

- transient terminal output;
- unverified guesses;
- temporary process IDs;
- entire logs;
- information already available clearly in source code unless it prevents a recurring mistake.

The public repository may be inspected at any time, but it represents the latest committed state and may lag behind local workstation changes.

When a proposed fix is not visible on GitHub and the user reports an error, ask whether the fix has already been applied locally before assuming the repository reflects the active code.

Working configuration:


## Factory dual-arm launch behavior

Factory launch:

```text
start_two_piper.launch.py
```

Factory defaults:

```text
can_left_port := can_left
can_right_port := can_right
auto_enable := true
rviz_ctrl_flag := false
girpper_exist := true
```

The factory launch only remaps:

```text
pos_cmd
joint_ctrl_single
```

Each `piper_single_ctrl` node also creates:

```text
enable_flag subscription
enable_srv service
```

Therefore, the factory launch is not observation-only.

The factory node constructor immediately:

- creates `C_PiperInterface`;
- calls `ConnectPort()`;
- creates control subscriptions;
- creates the enable subscription;
- creates the enable service;
- starts its publishing thread.

`auto_enable=false` prevents the automatic enable loop but does not make the node receive-only.

`ConnectPort()` calls `PiperInit()`.

`PiperInit()` sends query frames only:

- six motor angle and speed queries using CAN ID `0x472`;
- six motor acceleration-limit queries using CAN ID `0x472`;
- one firmware-version query using CAN ID `0x4AF`.

These 13 frames are non-motion queries.

They do not call:

```text
EnableArm
MotionCtrl
JointCtrl
EndPoseCtrl
GripperCtrl
```

## Joint and gripper interpretation

`/puppet/joint_left` and `/puppet/joint_right` use `sensor_msgs/msg/JointState`.

Names:

```text
joint0
joint1
joint2
joint3
joint4
joint5
joint6
```

Interpretation:

```text
position[0:6]  six arm joints in radians
position[6]    measured gripper feedback in metres
effort[6]      gripper effort feedback divided by 1000
```

Factory scaling:

```python
gripper_position = grippers_angle / 1_000_000
gripper_effort = grippers_effort / 1000
```

Small negative gripper positions may appear while physically closed.

Examples observed:

```text
left:  approximately -0.0023 m
right: approximately -0.0036 m
```

Preserve the raw value in recordings.

A GUI may display a separately clamped opening value for readability, but must not alter the recorded data.

## Factory Cartesian gripper concern

The Cartesian position callback contains a likely unit-clamping error.

It first computes:

```python
gripper = round(pos_data.gripper * 1_000_000)
```

but then compares the unscaled value:

```python
if pos_data.gripper > 100000:
```

This likely intended to compare the scaled `gripper` variable.

This does not affect observation mode.

Audit and correct the behavior before enabling Cartesian gripper commands.

## Episode storage contract

Recommended episode structure:

```text
episode_<id>/
├── bag/
│   ├── bag_0.mcap
│   └── metadata.yaml
├── episode.json
├── annotations.json
├── validation.json
└── recorder.log
```

Interpretation:

```text
bag/
  immutable ROS recording

episode.json
  stable episode-level metadata

annotations.json
  editable human or automatic labels

validation.json
  generated topic and timing validation results

recorder.log
  recording process output
```

Do not modify the MCAP when metadata or annotations change.

## Default shirt-folding stage vocabulary

Current seven-stage vocabulary:

1. grasp sleeve and shirt edge;
2. fold shirt over one third horizontally;
3. grasp inner folded edge;
4. fold shirt horizontally in half;
5. grasp left edge of shirt;
6. fold shirt in half vertically;
7. back away from folded shirt.

Do not hard-code the annotation system so tightly that only these seven labels can exist.

Support:

- a project default vocabulary;
- free-form natural-language labels;
- adding new stages;
- splitting and merging stages;
- adjusting stage boundaries.


## Future automatic annotation and SARM

Human annotation comes first.

Future automatic annotation should write the same sidecar format rather than introduce a second incompatible episode representation.

Preserve:

- natural-language stage labels;
- temporal stage boundaries;
- overall success labels;
- excluded ranges;
- annotation source;
- confidence;
- schema version.

This allows future stage-aware reward modeling or automatic subtask segmentation to consume the same episode data without mutating raw demonstrations.

## Known failure patterns

### Broad filesystem searches

Broad `find` commands under user homes can descend into environments, extensions, caches, and unrelated trees.

Use pruned, targeted searches.

### Source-inspection output explosion

Do not print overlapping context around every match.

Use exact method extraction, AST call summaries, or narrow `grep`.

### Long heredoc corruption

Long terminal heredocs can become interleaved, duplicated, or partially pasted.

Prefer small idempotent Python edits with assertions.

### Nested Markdown fences

When giving Markdown that itself contains triple-backtick blocks, wrap the complete response block in four backticks.

### Cascading command failures

If an early command fails, do not continue as though later commands succeeded.

Check the filesystem and process state first.

### Terminal paste artifacts

Characters such as:

```text
^[[200~
```

may be terminal bracketed-paste artifacts rather than program failures.

### Gitee authentication

Anonymous cloning of the factory Gitee remote failed with `Unauthorized`.

Direct LAN cloning from the original AgileX computer succeeded.

### Host-specific USB paths

Never copy USB bus paths from the factory computer to the new workstation.

Use stable serial identities.

### `auto_enable=false` assumptions

It prevents the automatic startup enable loop.

It does not remove command subscriptions or the enable service.

### Raw image `ros2 topic hz`

It can under-report real camera rate because the Python subscriber deserializes large image messages.

Use `camera_info` and MCAP counts.

### Duplicate camera launches

Cause duplicate node names, device-lock waits, and unnecessary load.

Refuse duplicates.

### Duplicate arm launches

Refuse to start when either expected Piper node already exists.

Only stop launch processes created by the current GUI.

### Orbbec uppercase `Log`

`list_devices_node` writes `./Log` in its current working directory.

Run it in a temporary directory.

### ROS setup under nounset

Source ROS before enabling `set -u`.

### `self.subscriptions`

It collides with a read-only `rclpy.Node` property.

Use `self._subscriptions`.

### GUI rate labels

Camera:

```text
Stream FPS
View FPS
```

Arm:

```text
GUI sample
```

Do not confuse GUI callback or render rates with MCAP recording rates.

### CAN parser whitespace

The `ip -statistics` header contains variable whitespace.

Regex patterns must use `\s+` between header fields.

### Cumulative CAN drops

Use deltas, not absolute historical totals.

### GitHub versus local state

The public repository may not include the user’s latest local edits.

Ask whether a suggested change has already been implemented locally before diagnosing based solely on GitHub.
