Factory node startup behavior
=============================
The dual-arm launch defaults to:

  can_left_port := can_left
  can_right_port := can_right
  auto_enable := true
  rviz_ctrl_flag := false
  girpper_exist := true

Never run the dual-arm launch normally until the safety wrapper and command
isolation are complete.

The factory node constructor immediately:
- creates C_PiperInterface;
- calls ConnectPort();
- creates command subscriptions;
- creates an enable subscription;
- creates an enable service;
- starts its publishing thread.

auto_enable=false prevents the automatic EnableArm loop, but does not make the
node receive-only.

ConnectPort() calls PiperInit() by default. PiperInit sends query frames only:

- six motor angle/speed queries using CAN ID 0x472;
- six motor acceleration-limit queries using CAN ID 0x472;
- one firmware-version query using CAN ID 0x4AF.

These are non-motion queries. They do not call EnableArm, MotionCtrl, JointCtrl,
EndPoseCtrl, or GripperCtrl.

Nevertheless, the node remains capable of motion through its command topics,
enable topic, and enable service.


Piper safety rules
==================
Before powering on:
- place both arms in the required horizontal/reset pose;
- manually close both grippers;
- keep the emergency stop immediately accessible;
- preserve all labeled USB connections.

Before replay or inference:
- physically disconnect/isolate both master-arm power plugs;
- verify the intended command topic and subscriber;
- verify message type, units, joint order, gripper representation, limits, rate,
  CAN mapping, start pose, and emergency-stop access.

In inference/replay mode, /master/joint_* and /puppet/joint_* are feedback topics,
not command topics.

Do not describe the existing Cartesian return script as safe from arbitrary
configurations. There is no validated local MoveIt 2 collision-planning setup.


Known failure patterns
======================
1. Broad filesystem searches
   Broad find commands under user homes can descend into Miniforge, extensions,
   caches, and other large trees. Use pruned, targeted searches.

2. Source-inspection output explosion
   Do not print overlapping context around every keyword match. Use exact method
   extraction, AST call summaries, or narrowly targeted grep.

3. Nested Markdown fences
   Shell heredocs containing Markdown triple-backtick fences can collide with
   outer Markdown formatting. Use four-backtick outer fences or avoid nesting.

4. Cascading clone errors
   If a clone fails, do not continue with cd, checkout, or sparse-checkout
   commands against the nonexistent directory.

5. Gitee authentication
   Anonymous cloning of the factory Gitee remote failed with Unauthorized.
   Direct LAN cloning from the original AgileX computer succeeded.

6. Host-specific CAN paths
   Never copy the original computer's USB bus paths to the new workstation.
   Use stable serial identities.

7. auto_enable=false assumptions
   It prevents the startup enable loop but does not remove enable/control
   subscriptions or the enable service.

8. Raw-image frame-rate measurement
   `ros2 topic hz` on sensor_msgs/Image can report severe artificial stalls
   because its Python subscriber must deserialize large raw frames. Validate
   camera cadence using camera_info and actual MCAP message counts.

9. Duplicate camera launches
   Starting multi_camera_rgb.launch.py while an existing copy is active creates
   duplicate node-name warnings, device-lock waits, and unnecessary processing.
   Run only one camera launch instance.

10. Orbbec default Log directory
    list_devices_node uses the SDK default configuration and writes ./Log in its
    current working directory. Run it from a disposable temporary directory.
    Normal camera launches use the configured logs/orbbec path.

11. ROS setup and Bash nounset
    ROS-generated setup scripts are not safe under `set -u`. Source the ROS
    environments first, then enable nounset.

12. rclpy Node property names
    Do not assign application state to `self.subscriptions`; Node exposes it as
    a read-only property. Use a private name such as `self._subscriptions`.

13. GUI frame-rate interpretation
    Stream FPS is measured from lightweight camera_info callbacks. View FPS is
    the deliberately capped preview-rendering rate. Neither should be confused
    with MCAP counts, which are the authoritative recording-rate measurement.
